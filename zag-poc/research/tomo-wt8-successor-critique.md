# WT8 successor: independent methodological challenge

SOURCE-ONLY / UNCOMPILED / UNEXECUTED; evaluation design, not a scored result. The user reports that the successor qualified its premise and its developmental heldout battery gave D1R 22/24 versus BEAM6 19/24. These figures are reports, not independently reproduced here. Unlike the predecessor, do not assume the premise is uninformative; do not assume that this small developmental gap establishes headroom beyond an authored revision. This document contains no heldout inputs, answers or secrets.

## Preregistered comparison

Freeze D1R, BEAM6, and an independent conventional active-test generator before selecting a fresh, independently generated scored battery. Stratify by task family, program and solution-template provenance, difficulty, defect class, and nominal oracle access. Keep seeds and implementation identities in the evaluation log; use paired instances and equalized total compute, oracle calls, time, memory and external information. Track every unsuccessful candidate, test and query as well as the selected answer. Do not tune after seeing scored outcomes. Publish the complete protocol, code and aggregate results after the secrecy window ends.

1. **First-passing ambiguity:** enumerate or sample distinct candidates that pass the visible evidence; log their predictions on independently generated counterexamples without revealing those counterexamples to the learner. Record how often the first passer is wrong, number of equivalence classes, and counterexample distance. Compare immediate commit, extra query, and calibrated abstention. If first pass already predicts heldout behavior reliably, revision has little useful room.
2. **Query value:** before each query record the candidate set and predicted outcome distribution, the actual observation, candidates eliminated and incremental accuracy. Compare information gain per oracle call and per second to cost-matched random and boundary-value queries. Only observable information may drive selection. A useful query must improve independent correctness after costs, not merely shrink syntactic diversity.
3. **Commit/abstain calibration:** require confidence before execution and retain every decision. Report reliability plots, Brier score, false-commit rate and risk versus coverage with confidence intervals. Compare against calibrated static thresholds and against an always-answer baseline. Declare costs of abstention and errors before the test; do not count a correct abstention as a solved task.
4. **Search depth and compute:** plot correctness against depth, samples, wall time, CPU and oracle calls, including overhead of revision. Provide matched-budget frontiers and an anytime baseline. If an improvement vanishes at matched cost or comes only from higher depth, it is not evidence for a uniquely useful revision mechanism.
5. **Independence and leakage:** cluster by normalized program structure, underlying defect, generator seed family and solution template, not merely input seed. Partition by cluster before any tuning; reserve an independently implemented generator and manually reviewed cases. Report cluster-level as well as per-task results; use a paired cluster bootstrap or exact paired test and disclose sample size. Repeated buggy programs/templates are correlated observations, not independent tasks.
6. **Conventional active-test generator:** maintain all currently consistent programs, generate legal test inputs that maximize candidate disagreement per unit cost, query the same oracle and update the version space; commit the simplest survivor or abstain when disagreement remains above a preregistered threshold. Supply a strong boundary-value and mutation-based generator as a second baseline, with identical language, oracle, visibility and budget. A conventional baseline matching or exceeding D1R on independent instances and matched cost falsifies the claim of unique advantage on this distribution.

## Success and failure criteria

Preregister a meaningful effect and uncertainty bound before looking at the scored battery. Report paired accuracy differences, confidence intervals, solved count, cost, coverage and failure modes; do not infer a win from a nominal 3/24 gap. Positive evidence requires a reproducible advantage over BEAM6 and the active-test baseline under equal information and budget on independent task clusters, with calibration and compute costs disclosed. A null, cheaper conventional winner, template leakage, low-value queries or substantial false commitments are substantive negative outcomes, not reasons to silently change the protocol.
