# Independent TNN growth and lineage evaluation contract

**Tier: SOURCE-ONLY / DESIGN / UNCOMPILED / UNEXECUTED / UNSCORED / NOT INDEPENDENTLY QUALIFIED.** This is a proposed evaluator contract, not an implemented evaluator, a new empirical result, or a qualified benchmark. No native execution command exists until an implementation and test fixtures have been supplied. Branch: `research/2026-10-30-tomo-zag-diagnostics`, chosen to keep evaluator work separate from release code. Inspection after checkout: `git show HEAD:zag-poc/research/tomo-tnn-growth-lineage-eval-2026-10-30.md`.

## Scientific question and custody

Determine whether the learner acquires and reuses information and learning machinery, rather than whether a researcher can author a stronger solver. Freeze learner, language interface, generators, prompts, rules, budgets and scoring before independent evaluation. Generate opaque random vocabulary and private per-instance rules from recorded seeds; do not expose evaluation seeds, answer keys, generators, logs or scorer to the learner. Store private material outside the learner's checkout and internet access. An independent evaluator commits hashes of a frozen private bundle before runs and reveals it only after the scoring window. Store hashes and signed, append-only records separately; a hash alone does not prove authorship, secrecy or execution.

Split by generator implementation, underlying structural family, domain and solution template, not merely random seed. Include a separately implemented heldout generator and fresh vocabulary; prevent a model from obtaining answers by guessing common English associations. Randomize symbol-to-role mappings and pair instances with identical questions but different taught facts. A fixed pretraining-derived answer cannot pass both. Freeze a priori sample size, stopping rule, success margins and paired analysis. Cluster uncertainty by task family rather than treating correlated questions as independent.

## Interfaces and exact measurement

Structured core interface: a sequence of typed events (`teach`, `query`, `correct`, `restart`) with opaque string identifiers and machine-checkable objects. Conversation interface: an equivalent natural-language rendering. Score core separately from end-to-end conversation; log the translator's structured input/output, all learner questions, replies and state transitions. No internet, ground-truth files or cross-instance state during heldout evaluation unless explicitly allowed for every comparator. Restart means terminate the process, then start a clean process with only the allowed persistent state mounted. Record process IDs, file hashes and retention access logs; same-process reinitialization is not restart evidence.

Each query returns a canonical JSON value or an explicit `abstain`; unknown is not the same as false. Exact comparison after specified canonicalization: ordered sequences remain ordered, sets are sorted and deduplicated, and identifiers are exact strings. Report exact-correct, wrong, abstained, malformed, clarification-needed and clarification-correct counts separately. A correct abstention never counts as a solved task. Predeclare costs for errors, questions, abstentions, wall time, CPU, memory and oracle calls. Unanswered queries score zero; failed compilation or invalid output is not a correct answer. For causal/plan/program tasks validate against executable independent models rather than a textual explanation judged by intuition. Primary outcome is heldout functional correctness; calibration, cost and efficiency are secondary. Independently blind scorer and freeze predictions before revealing keys.

## Generated test families and controls

For every family below, generate many instances with unseen symbols, randomized mappings and varied structure; supply enough teaching to make queried answers unique unless explicitly testing clarification. Use matched counterfactual pairs that differ in one taught fact or rule, with identical query forms. Record generated instance, ground truth, transcript and state identity privately. These are exact acceptance specifications, not evidence that an implementation exists.

1. **Novel concept / binding:** create symbols `a,b,c` and opaque unary category `Q`; teach `Q(a)=true`, `Q(b)=false`, `Q(c)=true`; ask for the members. Exact answer `{a,c}`. Bind `x=b`, then update `x=c`; query `Q(x)` after each and score `[false,true]`. Counterbalance mappings and number/order of facts.
2. **Dialogue memory, rules, exceptions and correction:** teach `P(v) => R(v)`, `P(a)`, `P(b)`, then `exception(b, R)` with explicit rule that the exception overrides the implication. Score `R(a)=true`, `R(b)=false`; later correct the exception from `b` to `a` and score `R(a)=false`, `R(b)=true`. Interleave irrelevant turns. Undefined facts produce `unknown`, not inferred false. Vary exception priority and the number of intervening turns.
3. **Clarification:** present a query where two previously taught relations could each be the referent and give no disambiguating information. A valid clarification must name a distinction that yields different predictions; the teacher answers according to the hidden relation. Score the question and the resulting exact answer separately. A premature answer is wrong even if it guesses correctly; when the reference is unique, an unnecessary question incurs its declared cost.
4. **Causal explanation:** teach an acyclic Boolean structural model, e.g. `B=A AND NOT C`, `D=B OR E`, plus values for exogenous `A,C,E`; ask the effect of `do(C=1)` and require the exact post-intervention values and a minimal changed causal path. Independently recompute after replacing C's equation/value with the intervention. Randomize operators, graph topology and variable names; paired intervention-free observations distinguish association from causation.
5. **Restart and long horizon:** ask a subset immediately, terminate, remount only permitted persistent state, then ask new compositions after many irrelevant facts and turns. Compare same saved checkpoint with an erased-knowledge state while preserving identical code and process environment. Score novel consequences, not only repeated answers; log retained/forgotten versions and subsequent correction consistency.
6. **Cross-domain transfer:** teach the same abstract relations under independently rendered inventory, routing and symbolic-grid vocabularies, then query a new topology and symbol mapping; transfer must be measured against a scratch learner on the same target examples and budget. An independently generated heldout structural family is required; mere renaming is not sufficient evidence of structural transfer.
7. **Plan construction:** supply a finite directed state graph, start, goal, permitted actions and costs. Return an ordered action list. Independently simulate each action and check that it is legal and reaches the goal; report cost and compare to the independently computed shortest path. Include unsatisfiable cases, for which `no_plan` is correct only when the independent search exhausts the finite graph. Change topology at heldout time.
8. **Program synthesis:** provide a finite grammar, typed input/output signature, and examples from a newly taught rule. Require a program in the permitted grammar; run it in a sandbox on independently generated heldout inputs. Exact output equality is primary; nontermination, resource exhaustion and illegal operations fail. Generate family splits so memorized lookup tables and selected authored templates are separately measured.
9. **Learning a method from failure:** present a novel deterministic search task with a bounded legal query budget and an informative negative feedback event. Require a logged candidate procedure before and after feedback. Evaluate both frozen procedures on matched new instances, including cases with different input order. Charge proposal, testing and execution cost; a researcher-selected patch is not a learner-generated method. Random guessing, an unchanged procedure and conventional active testing are controls.
10. **Learning the learner:** run the two-generation lineage test below on new task families and compare each frozen generation to preregistered rollback controls. Neither two state writes nor two executions of the same fixed authored rule alone qualifies as recursive improvement.

## Required ablations and comparators

Use paired instances, seeds, identical task descriptions, interfaces, resource budgets and evaluation. A: erase acquired knowledge only; preserve source, procedure and unrelated state. B: erase the invented procedure only; preserve knowledge and unrelated state. C: restore old representation with semantic migration verified on a neutral probe; equalize compute, memory and observations, and measure conversion costs. D: restore generation-0 learning rule while preserving all other generation-1 state; compare the actual second-generation proposal and heldout outcomes. E: new independently implemented generator, data structure and domain; distinguish transfer from within-family generalization. F: frozen language-interface model alone, without TNN's acquired state, receives exactly the same teaching and interaction budget; also test structured core without the language interface. For each ablation hash the before/after state and verify the intended removal plus preservation of unrelated state; if preservation cannot be demonstrated, mark that control invalid, not negative evidence.

Use strong separately implemented baselines where feasible: active automata/version-space learning, CEGIS with a constraint solver, test-guided program repair, planning/search, probabilistic belief revision, retrieval with durable memory, and an appropriately budgeted competent coding/language model. Give each equal task information, tools and budget; report unimplemented baselines as missing, not losses. Track learned content and author provenance for each baseline. Do not equate an aggregate advantage with demonstrated general intelligence.

## Lineage verifier: compact record and decision rules

One append-only JSONL record per event, canonical UTF-8 JSON, with `schema`, `event_id`, `parent_event_hash`, `generation`, `producer`, `timestamp`, `source_identity`, and an `artifacts` array of `{role, uri, sha256}`. Artifacts must include: parent learner source and executable identities; learner-visible problem and information boundary; triggering failure/opportunity and raw logs; exact proposal and producer transcript; source/procedure artifact; compiler/toolchain identity and build command, exit status, stdout/stderr and output hashes; independent evaluation protocol, evaluator identity and sealed instance hashes; adoption decision and signer; modified learner source and binary hashes; heldout new-family results; and links to child events. If unavailable use explicit `unknown` and fail the relevant verification gate. Hashes establish integrity, not identity, causation, independence or author origin. Signed provenance, access logs and independent human review are required before making those stronger claims.

Validation: verify hashes against actual artifacts, parent-child identities, time order, absence of editing after freeze, reproducible build where practical, raw evaluation and scoring, and independent custody. Categorize by evidenced producer: (1) researcher-authored modification; (2) learner-selected authored upgrade; (3) learner-composed executable procedure from authored primitives; (4) learner-generated change to the learning algorithm; (5) consecutive learner-generated improvements to learning machinery. Categories 1–3 do not establish 4 or 5. Reject or mark unverified whenever provenance, build, independence, task-family split or actual adoption is missing. A proposal alone is not an adopted improvement; an adopted change is not an independently measured improvement.

## Two-generation dependence test

Freeze G0, problem family A, and an independent evaluator. G0 receives a failure signal and generates a concrete change to its learning machinery; preserve proposal, build, adoption and G1 identities. On predeclared unseen family A' and matched budgets, independently verify a meaningful G1-vs-G0 improvement and no disqualifying regression on retained functions. Freeze all before revealing outcomes. Then G1 faces disjoint family B and generates a second *different* change to learning machinery, producing G2. Freeze G2 and evaluate on unseen B' and retained A' under matched budgets, including errors, cost and confidence intervals. Run the paired rollback from the same G1 checkpoint: replace the first changed learning mechanism with G0's version while holding state, observations and compute constant, then attempt the identical generation-2 challenge across randomized seeds. A credible dependence claim requires preregistered evidence that the verified G1 mechanism causally affects the second modification's production or its independently measured improvement; compare accepted proposal identity and B' gains. Failed rollback equivalence, author intervention, reused fixed update logic, selection bias or non-reproducible effects leave the claim unverified. Repeated procedure updates alone are not RSI.
